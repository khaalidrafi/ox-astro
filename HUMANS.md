# HUMANS.md

A guide for human developers who did not write this code. Written
from a fresh read of the sources on 2026-11-18, per the Owner's
order that agents explain AI-developed codebases.

## What this is

An Emacs Lisp package that exports Org mode files to Markdown with
front matter for the Astro static site generator. It is a fork of
ox-hugo (kaushalmodi/ox-hugo) reworked for Astro: front matter
defaults to YAML, the key set follows Astro's content collection
schema (title, description, pubDate, updatedDate, draft, tags, ...),
and heading slugs are generated by a port of github-slugger because
Astro derives content collection entry ids from file names the same
way GitHub derives heading anchors.

The fork's second mission is org-roam support. Each exported "unit"
(a post subtree or a whole file) that carries an org-id gets
`roamID` and `roamLinks` front matter keys, `id:` links in the body
become `/blog/<slug>/` links, and an interactive command writes the
whole link graph as JSON for a layout to render backlinks at build
time.

Almost everything lives in one file, `ox-astro.el` (about 5,360
lines). `README.org` and `CHANGELOG.org` still carry upstream
ox-hugo text, so read them for background, not for Astro specifics.
`AI-REVIEW.org` records the fork history and what has been ported so
far; it says the `.astro` component writer (plan step 3) is still
open.

## Mental model

The package defines one Org export backend named `astro`, derived
from the built-in `md` backend (`org-export-define-derived-backend`
near line 1155 of `ox-astro.el`; the chain is astro < md < html).
Org's export engine walks the parse tree and calls a transcode
function per element type; the backend's `:translate-alist` maps
about a dozen element types (headline, link, paragraph, src-block,
table, ...) to `org-astro-*` functions that override the Markdown
defaults.

Two export flows share that backend:

- one-post-per-subtree: a subtree with an `EXPORT_FILE_NAME`
  property is a "valid post subtree" and exports to one file.
- one-post-per-file: a file with `#+title` and no valid post
  subtrees exports as a single post.

The interactive entry point is `org-astro-export-wim-to-md`
("What I Mean", bound to `C-c C-e H H`): it picks the flow from the
buffer state, exports the subtree under point, all valid subtrees,
or the whole file (`org-astro-export-wim-to-md`, line 5225).

Data flow for one export:

1. `org-astro--before-export-function` (line 1444) installs
   temporary advice around Org Babel / org-cite internals and
   memoizes the roam unit table for this export.
2. The roam table (`org-astro--get-roam-table`, line 4572) scans the
   buffer once and builds an alist of `(ID SLUG TITLE)` triples,
   one per export unit that has an org-id.
3. `org-astro--get-front-matter` (line 4240) assembles the front
   matter alist: sanitized title, dates run through
   `org-astro--format-date`, tags/categories from Org tags or
   `ASTRO_TAGS` / `ASTRO_CATEGORIES`, draft state from the TODO
   keyword, plus `roamID` / `roamLinks` from the roam table, plus
   any `ASTRO_CUSTOM_FRONT_MATTER` pairs.
4. `org-astro--gen-front-matter` (line 4420) renders that alist as
   YAML (`org-astro--gen-yaml-front-matter`, hand-rolled) or TOML
   (via the external `tomelr` package).
5. Org transcodes the body to Markdown; `org-astro-link` (line
   3131) is the busiest transcoder: it resolves `id:` links through
   the roam table to `/blog/<slug>/`, rewrites cross-file links,
   copies images, and so on.
6. `org-astro--after-1-export-function` removes the advice and
   clears the per-export state, including the roam table cache.

Output placement: files land under `<base-dir>/<content-folder>/<section>/`
(defaults: `org-astro-base-dir` nil, `org-astro-content-folder`
"content", `org-astro-section` "posts"), overridable per file or
subtree with `ASTRO_BASE_DIR`, `ASTRO_BASE_CONTENT_FOLDER`,
`ASTRO_SECTION`.

`org-astro-auto-export-mode.el` is a small minor mode that re-runs
the export on every save via `after-save-hook`.

## Core algorithms

Slugging. `org-astro--slugify` mirrors github-slugger's `slug()`:
downcase the string, keep characters matching
`org-astro--slug-keep-re` (Unicode letters and digits via Emacs
`[:alpha:]` / `[:digit:]`, plus `_` and `-`), also keep chars whose
Unicode general category is `Nd` (Emacs's `[:digit:]` is ASCII-only,
github-slugger's is not), turn spaces into hyphens, drop the rest.
It walks the string one char at a time with `mapconcat`, so it is
linear in input length. `org-astro-slug` wraps it with the
github-slugger occurrence map: a hash table from base slug to count,
so a second "My Post" becomes "my-post-1". The hash is process-wide;
`org-astro--slug-reset` clears it and is called at load time.

Roam table. One scan per export, memoized in the dynamic variable
`org-astro--roam-table` by `org-astro--before-export-function` and
invalidated by `org-astro--after-1-export-function` and
`org-astro--cleanup`. If the buffer has any valid post subtree, it
runs `org-map-entries` over entries matching `EXPORT_FILE_NAME<>""`
and collects those with an `ID` property; otherwise it falls back to
the file-level property drawer id plus the `#+title`. Complexity is
a single pass over entries plus property lookups. Units without ids
are simply not in the graph; ids from other files never resolve,
which mirrors org-roam's rule that only id-carrying nodes link.

Front matter assembly. `org-astro--get-front-matter` is a large
`let*` that pulls values from the export info plist, then walks Org
tag group alists (`org-tag-groups-alist`) to expand group tags into
both tags and categories, applies user key-replacement
(`ASTRO_FRONT_MATTER_KEY_REPLACE`), and hands the alist to the YAML
or TOML writer. The YAML writer is a straight recursive descent over
the alist: nested alists recurse one level with two-space indent,
flat lists render as flow sequences, scalars go through
`org-astro--yaml-scalar`. There is no block-style list rendering;
everything is inline `[...]` sequences.

Link translation. `org-astro-link` first computes `roam-slug` by
looking up the link's path in the memoized roam table; a hit means
the target is a sibling export unit of the same buffer, and the
link renders as `[desc](/blog/<slug>/)` or `<URL>` when there is no
description. Everything else (custom-id, fuzzy, file, http, coderef)
follows the ox-hugo logic inherited from upstream.

Graph export. `org-astro-export-roam-graph` recomputes the table
from scratch (it does not trust the export-time cache), then for
each post subtree narrows to that subtree and collects `id:` links
whose target id is also a table member, skipping self-links. Edges
are deduped with `delete-dups` and the result is written with
`json-encode` and pretty printing enabled.

## Invariants and gotchas

- `org-astro-auto-export-mode.el` was never adapted to the fork. Its
  after-save hook calls `org-hugo-export-wim-to-md`, a function that
  does not exist in this repo (it lives in upstream ox-hugo, and the
  file even `declare-function`s it against "ox-hugo"). Do not
  enable this mode unless ox-hugo is also installed, or fix the
  names first.
- The slug dedup state (`org-astro--slug-occurrences`) is
  process-global, not per-export. Two exports in one Emacs session
  can influence each other's slugs; call `org-astro--slug-reset`
  between them if that matters.
- The roam table cache is cleared after every export on purpose
  (`org-astro--cleanup` drops it so a stale table cannot leak into
  the next buffer's export). If you add a new consumer, read it
  through `org-astro--roam-table`, not `org-astro--get-roam-table`
  directly, so you get the cache.
- `roamLinks` only resolves ids that are export units of the *same
  buffer*. Links to other files or to non-post headings silently
  keep their normal Org resolution. That is by design (documented in
  `org-astro--get-roam-links`), not a bug.
- Bundle landing pages (`index` / `_index` file names) must set
  `EXPORT_ASTRO_SLUG` explicitly; the derived slug would otherwise
  be "index" (see the docstring of `org-astro--unit-astro-slug-at`).
- `org-astro-export-roam-graph` is not wired into the export
  commands. You must call it yourself after exporting a buffer. This
  is listed as "the next cut" in `AI-REVIEW.org`.
- TOML output depends on the external `tomelr` package; YAML output
  does not. The `require` of tomelr is soft (`:noerror`), so a
  missing tomelr only breaks TOML-format exports.
- Front matter key order is the order of the literal alist in
  `org-astro--get-front-matter`; the comment there says Hugo-only
  keys (menu, weight, outputs, ...) are intentionally not emitted
  even though the options-alist still parses their keywords.
- Tests compare committed output: the `do_test` target re-exports
  every Org file under `test/site/content-org/`, overwrites
  `test/site/content/`, then diffs a copy (`content-modified`)
  against a golden snapshot (`content-golden`) and restores
  `content/` from git. If you change export output, expect
  `git status` noise in `test/site/content/` after a test run.
- The CI workflow triggers on pushes to `main` and on all pull
  requests. Work in this org lands on `ai/main` (see below), so CI
  runs on PRs from ai/ lanes, not on trunk pushes.

## Developing

Commands (from the Makefile; `make` alone prints help):

- `make test` - full check: version check, ERT suite, rebuild
  golden files, re-export all test Org files and diff against
  golden.
- `make ert` - ERT tests only (`test/ert/all-tests.el` loads
  tanchor, tfm, tslug, telement, troam suites).
- `make vcheck` - print Emacs and Org versions.
- `make md` - re-export all test Org files without the golden diff.
- `make testmkgold` - rebuild `test/site/content-golden` from the
  current `content/`.
- `make FOO.org` - export one Org file.
- `make doc` / `make doc_md` / `make doc_gh` - regenerate the
  documentation site content (finicky; CI does not run it).

Requirements: Emacs 26.3+ (CI tests release snapshot, 29.4, 28.2),
Org 9.0+, `tomelr` 0.4.3+ for TOML front matter. The test setup
loads `test/setup-ox-astro.el` in batch mode with `HOME` pointed at
`test/` and expects the environment variables `OX_ASTRO_TMP_DIR`
and `TEST_ENABLED` (the Makefile sets both).

Branch law (from `AI-REVIEW.org`): `ai/main` is the fork trunk.
Docs-only commits land on it directly from the AI lane; code
changes ride named `ai/` lanes and merge after review. Never push to
`main`.

The ERT suite for the roam subsystem (`test/ert/troam-astro.el`)
was written in a sandbox without an Emacs binary and, per
`AI-REVIEW.org`, had not been run there; treat CI as the first
authority on whether it passes.
